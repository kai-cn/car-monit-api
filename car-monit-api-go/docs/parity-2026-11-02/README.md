# Java ↔ Go 全接口对比校验（2026-11-02）

对照对象：`pro-business-api`（Java / Spring Boot，**:9902**）与 `car-monit-api-go`（Go / gin，**:9903**）。
本轮从头重做，不复用 10 月 `_probe` / `_probe_go` 的结论。

## 结论摘要

- **路由层 100% 对齐**：Java 85 个端点，Go 85 个，无缺漏无多余；`{agentPk}`/`{bigId}`/`{ds}`/`{taskId}` 等变量名一致，前端无需改 baseURL。
- **序列化可信**：358 条用例中 **TYPE / 数值精度 / 结构形状差异 0 处**（日期格式、Long 转字符串、空数组、信封都对得上）。
- **实测跑了 14 轮**（含 3 次复跑确认，判定逐条一致），`OK` 从 **208 → 329**（定稿 364 条）：
  初测 208 → 拉平缓存 208（判定不变但归因改变）→ 修分页/过滤 287 → 修工具假差异 310 →
  修请求体契约与日期绑定 314 → 补 sysutil 边界用例 315 → 修轨迹 `total` 语义 317（r10）→
  修 `null` vs `""` 与统一查询错误契约 **329**（r11）→ 补 3 条时间格式用例（r12，共 364 条）。
  DIFF 101→13，STATUS 27→22，NONDET 22→**0**。
  **零回归的说法要收紧**：相邻比对中有 3 次出现过 OK→非OK（`final→r3` 暴露轨迹投影少 15 列，
  `r3→r4` 是我把日期绑定接宽了 2 条，两者后续都已修复）；自 `r5` 起到定稿的 r12，
  相邻比对**零回归**（r9→r10 2 条 DIFF→OK、r10→r11 12 条 DIFF→OK、r11→r12 零迁移）。
  准确表述是 **修复过程有抖动、全部已收敛，最终态零回归**（见 `08` §3.3、`09` §4.3、`10`）。
- 累计修掉 **19 项**：分页 5（截断 / `pageSize<=0` / 越界回夹 / `orderByColumn` 忽略 /
  **轨迹 `total` 用 count 而非页行数**）、过滤 3
  （`trailtracks` 丢条件、绑定错误静默吞、日期参数绑定按实测矩阵重写）、
  契约 4（非法请求体 400、结尾斜杠、**`TrailBo`/`TrailInfo` 的 null 三态**、
  **统一查询降级失败不再冒 500**）、
  轨迹链路 4（`captureTime` 恒空、Go 自补 ORDER BY 换行、**历史轨迹少投影 15 列**、相对时间窗缺上界）、
  其余 3（行 `id` 32 位无横线、模糊词表、假断言重做）。
- **剩余 35 条已无一条是"数据算错"**：22 条是 Java 自身 500、6 条是 404/405 响应体形状（待拍板）、
  4 条是 Java 降级 SQL 表名缺 schema（Go 正确）、3 条是 Java 的 `Timestamp.valueOf` 只认完整时间格式
  （Go 更宽、真能查出数据，待拍板是否复刻）。逐条映射见 `10` §6（`09` §5 是 r10 口径、`07` §7 是 r9 口径）。
- 轨迹富集链路实测已完全一致：`carTrackQueryByTime` 按车牌对齐后 **94/94 行内容零差异**；
  曾经 `trailList` 内残余的 **256 处** `Java null ↔ Go ""` **已在第五轮归零**（`10` §2）。
- **22 条 STATUS 全部是 Java 侧本身 500**（mapper 缺 bound statement、别名当列名），Go 反而能用；
  这类不能简单要求 Go 复刻，需按业务决定。
- 初测的 **22 条 NONDET 已归零**：查明是工具假差异（行 `id` 每次重新生成不能当主键）+
  基准端自身不可复现（共库 + 调度在写 + 多数 mapper 无 ORDER BY），不计入 Go 缺陷。
- 环境结论：Java 与 Go 的 Redis 分库后**缓存状态并不等价**
  （`sys_config:data_query` 只在 db1、`car_list_jc` 只在 db0），导致 `total=251 vs 900`、
  `carTrackQueryByTime` `112 vs 0` 这类"看起来像代码差异、其实是状态差异"的结果。
  且本机有共驻服务每 30 秒清空 db0 的 `sys_config:*`，**拉平只能动 Go 自己的 db1**。

```bash
cd car-monit-api-go/docs/parity-2026-11-02/tools
python parity.py --gen && python parity.py --out r12 --md ../raw/r12.md   # 364 条
python suite2.py
python routes.py > ../raw/routes.txt
python predicates.py
python export_probe.py
```

> 改过 `suite.py` 必须先 `--gen`：`parity.py` 优先读缓存的 `cases.json`，
> 不重新生成会**静默用旧用例表**（第五轮第一次跑 r12 就因此少跑 3 条）。

写接口默认不执行（`--allow-write` 才跑），避免在共用库上触发全量同步、覆盖 Java 写入的 ES 文档。
