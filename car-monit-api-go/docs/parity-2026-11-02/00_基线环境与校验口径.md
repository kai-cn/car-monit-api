## 2. 数据源与缓存隔离

| 依赖 | Java | Go | 是否一致 |
|---|---|---|---|
| GaussDB | `jdbc:postgresql://192.168.56.10:5432/RuoYi`，user `gaussdb` | 同库同用户 | **共用同一数据库** ✅（符合约定） |
| Redis 实例 | `127.0.0.1:6379` | `127.0.0.1:6379` | 同实例 |
| Redis **db 编号** | `database: 0` | `database: 1` | **不同库** ✅（符合约定，实测 db0=2510 keys / db1=1275 keys / db2=1 key） |
| Elasticsearch | `localhost:9200`，索引 `snapshot_flow`/`fee_records`/`trail_fitting` | 同 | 共用 |
| Kafka / Pulsar / RocketMQ / RabbitMQ | 配置存在 | 配置存在 | 见第 5 节 MQ 侧影响 |

Redis 隔离的理由（`config.verify.yaml` 注释）：两端沿用同一套 key 名（如 `DATE_BorderWeighingCapture:<uuid>`），
但序列化格式不同 —— Java 走 fastjson2（带 `@type`），Go 走普通 JSON。若同库，
`/base/vehicleweight/map` 这类接口的结果取决于「谁最后写入该 key」，比对不可复现。
分库后 Java 读到自写缓存，Go 落到自己的空库回源 DB。

> 这条隔离是**比对期的手段**，不是运行期结论。生产上如果 Java/Go 灰度并存且要求共享缓存，
> 必须统一序列化格式或加 key 前缀，见 `04` 问题清单 P-REDIS-*。

## 3. 基线可信度

- Java jar 构建时间 `2026-10-31 12:47`；`find ... -newer <jar>` 在 `pro-business-api/src`、`pro-base-common/src`（含 `*.xml` mapper）上**无更新文件** → 运行中的 jar 与当前源码一致，可作为基准。
- Java 侧 `@RestController` 全部位于 `pro-business-api/src/main/java/com/ruoyi/base/controller`，共 **24 个 Controller**；`pro-base-common` 的 `BaseController` 是抽象基类，不提供路由。
- Go 侧路由由 `internal/router/router.go` 显式装配 4 组 handler + 健康检查 + pprof。

## 4. 校验口径

1. **存在性**：路径 + HTTP 方法在两端是否都存在（含 Spring 的 404/405 语义）。
2. **契约**：入参名、必填性、默认值、类型；响应信封（`AjaxResult` / `TableDataInfo` / 裸对象 / 裸数组）。
3. **行为**：同参数打两端，逐字段比对（按主键对齐，不比整行字符串）。
4. **语义**：读两端实现比对 SQL/过滤/排序/分页/空值/时间格式/数值精度/Redis key 与 TTL/ES 索引选择/定时任务。
5. 判定分级：
   - `BLOCK`：接口缺失、500、结构性不兼容，前端或调用方会直接坏。
   - `DIFF`：响应内容或类型不一致，需要确认哪端正确。
   - `WARN`：值相同但实现路径/边界条件不同，当前用例覆盖不到。
   - `OK`：等价。

## 5. 已知非 HTTP 面差异（本轮记录但不逐条实测）

MQ 消费端、21 个定时任务、导出文件目录（Java `/data/export` vs Go `./data/export`）不在 HTTP 差分范围内，
但会影响「同一时刻两端读到的数据是否可比」。见 `03` 语义校验章节的 MQ/调度小节。

## 6. 基线环境的三处不干净（详见 03/04）

1. **Java 的 db0 缓存被历史探针污染**：`car_list_jc` 内含合成车牌 `PARITY_UP_x3c1r`/`PARITY_UP_7gslo`，
   另有 `car_sync_time:PARITY_UP_*`、`car_history_trail:PARITY_UP_*`。以 `total=112` 当基准会高估差异。
2. **`application.yml:139` 的 JedisCluster `36.200.31.15:22400` 实测不可达**，与 `spring.redis` 本地库是两条通道。
3. **`configs/config.yaml`（默认那份）仍是 `port:9901` + `redis.database:0`**，误用会抢端口并覆写 Java 缓存。
