# 01 路由清单对比（Java 85 ↔ Go 85）

提取方式：`tools/routes.py` 直接扫源码 —— Java 侧解析 `@*Mapping` 注解（先用 `strip_comments()` 剥掉
`/* */` 与 `//` 注释，避免把注释里的历史接口算进来），Go 侧解析 `ReadOnlySpec` 注册表 + 各 handler 的
`grp.GET/POST`。清单原文见 `raw/routes.txt`。

## 1. 总量

| | 数量 | 说明 |
|---|---|---|
| Java 端点 | **85** | 24 个 Controller |
| Go 端点 | **85** | 4 组 handler |
| 路径 + 方法匹配 | **85 / 85** | 覆盖率 100%，无缺漏、无多余 |
| Go 侧额外 | `/healthz` `/readyz` `/health` `/debug/pprof/*` | Java 无 Actuator，属 Go 新增探针，不影响业务契约 |

`/api/v1/unified/{ds}/list` 与 Go 的 `/api/v1/unified/:ds/list` 是同一条路由的两种写法
（脚本按字面比对才报成「缺」），实测已验证两端均可用（见 `02` 第 3 节 unified-* 用例）。

## 2. 注释态接口的处理（易错点，已逐条验证）

Java 源码里有 3 处**写在注释块中**的映射，它们不是接口，Go 侧也不应注册：

| 位置 | 内容 | Java 实测 | Go 实测 | 判定 |
|---|---|---|---|---|
| `SysUtilController.java:39-70` | `POST /base/sysutil/syncTrack`、`POST /base/sysutil/syncSuspiciousCar` 整块被 `/* */` 包住 | 404 | 404 | ✅ 两端一致，Go 不注册是对的 |
| `task/CarTask.java:1-231` | 整个文件被 `/* */` 包住 | `target/classes/.../task/` 只有 `TrackTask.class`、`DataFlowTask.class`，**没有 `CarTask.class`** → 调度从未生效 | `jobs.go` 注册但 `Disabled:true` | ✅ 等价 |
| `WebConfig.java` / `SecurityInterceptor.java` | 全文注释 | — | Go 无鉴权中间件 | ✅ **两端零路径鉴权**，不存在「Java 要 token、Go 不要」的风险 |

## 3. Go 侧的 501 桩（12 个）

`/base/sysutilTest` 共 15 个端点，Go 实现 3 个（`syncBaseInfo` / `syncCurrentTrack` / `syncHistroyTrack`），
其余 12 个（`syncSuspiciousCar1..10`、`syncOdsSzdnGantry`、`separateSnapshotFlowTimeList`）
注册为 **501 桩**（`internal/handler/selftest.go:118-127`）。

路由存在性用 **405 探针**验证（发 POST 只看状态码，不触发 handler，避免在共用库上触发全量同步）：
20 条 exists 用例全部 OK —— **Go 有路由并返回 501，Java 有同名路由**。
差异在行为层而非路由层，逐条复核见 `03` 第 4 节。

## 4. 信封契约分布（决定响应结构能否直接比）

Java 方法返回类型统计（`raw/routes.txt` 末段）：

| 返回类型 | 数量 | 响应结构 | Go 对应手法 | 实测 |
|---|---|---|---|---|
| `AjaxResult` | 19 | `{code,msg,data?}`，`data` 为 null 时**整个键消失** | `response.Ok/Fail` | ✅ 一致（`/base/gantry/18` 两端都是 `{"code":200,"msg":"操作成功"}`） |
| `TableDataInfo` | 24 | `{total,rows,code,msg}` | `crud.go` 同构 | ✅ |
| `Map<String,Object>` | 13 | 裸对象（large/unified 查询族） | `query.go` 裸 JSON | ✅ |
| `void` | 15 | HTTP 200 + **空 body**（sysutilTest 全部） | Go 返回 `AjaxResult` | ❌ 契约不同 → `04` P-ENV-1 |
| `List<T>` 裸数组 | 8 | `/listAll`、`/listToExport`，无信封 | `AllowAll` / `AllowExport` | ✅ |
| 裸实体（`OdsSzdnGantry` 等 3 个 + `TrailBo` + `TrailInfo`） | 5 | 无信封 | `FlatInfo` | ✅ |

## 5. 参数命名契约的一个坑

`CarParaVO`（`/base/sysutil/carTrackQueryBy*` 的入参对象）里有**拼写错误且类型可疑**的字段，
Go 侧**如实复刻**了，这是对的，但会误导测试：

| 字段 | Java (`CarParaVO.java`) | Go (`model/car_para_vo.go`) | 说明 |
|---|---|---|---|
| `starTime` | `Integer` L45 | `*int` L22 | 拼写少了一个 `t`（不是 `startTime`），且是整型 |
| `endTime` | `Integer` L48 | `*int` L23 | 整型，**不是时间串** |
| `applyTime1/2` | `String` L20/22 | `string` | 真正的时间区间走这两个字段 |
| `lastExitTime` | `Date` L62 | `*Timestamp` | |

> 后果：`?endTime=2025-10-01 00:00:00` 在 Java 侧触发 Spring 类型转换失败 → **HTTP 400**；
> Go 侧 `setByString` 解析失败后**静默忽略** → HTTP 200。本轮第一版用例就踩了这个坑，
> 已在 `02` 第 5 节按真实契约重跑。这个「宽容度差异」本身是缺陷 → `04` P-BIND-3。

## 6. 结论

路由层面**没有缺口**：路径、方法、变量名（`{agentPk}` `{bigId}` `{dataSource}` `{uuid}` `{taskId}` `{ds}`）
全部对齐，前端无需改 baseURL。所有不一致都发生在**行为层与契约层**，见 `02` / `03` / `04`。
