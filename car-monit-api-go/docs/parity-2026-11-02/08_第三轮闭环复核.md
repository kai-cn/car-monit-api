## 3. 抓出的四个问题

### 3.1 `P-FILT-5` 的断言是空的（最严重）

`TestCarNoAndCarNoListAreIndependentAnds` 原来只做一件事：在全文件里 grep 一个固定串
`} else if utils.IsNotBlank(vo.CarNo)`。而我手工把代码改回**真实的历史写法**
`} else if len(vo.CarNoList) > 0 {` 之后，**测试照样通过**。

也就是说 `P-FILT-5` 这一格登记的"断言闭环"、以及 `07` §3C 写的"删掉后测试确实 FAIL"，
当时对它并不成立 —— 这条修复完全没有任何可执行证据。

已重写为：把断言锁进 `GetHistoryTrail` 函数体，要求两个过滤条件之间**不出现 `else`**，
且第二个 `if` 必须紧跟在 `}` 之后。

### 3.2 这批源码文本断言在 Windows 检出上会假失败

仓库 `core.autocrlf=true`，`git checkout` 之后 `.go` 文件在工作区是 **CRLF**。
断言按行切源码，CRLF 下 `TrimRight(before, " \t\n")` 留着半个 `\r`，
新写的 `P-FILT-5` 断言在干净代码上就直接失败了 —— 我这次是靠这个假失败发现的。

已修：`mustSource()` 统一 `\r\n` → `\n`，所有源码文本断言与检出平台的行尾无关。

> 顺带一个建议（**未执行**，属仓库级配置，需要你拍板）：加 `.gitattributes`
> 写明 `*.go text eol=lf`。否则任何人新克隆这个仓库，`gofmt -l` 会把**所有** `.go`
> 文件列为待格式化，`make lint` 之类的检查会一片红——这跟迁移质量无关，纯粹是行尾。

### 3.4 P-PAGE-8 的影响面被写小了

原来记成"3 条轨迹 total 语义"，读起来像只有 `pageSize=0/-1/越界` 这种边角才会碰到。
实际上 `carTrackQueryByTime` 的**默认首页请求**（`pageNum=1&pageSize=5`）就在带这条差异：
`total` Java **112** / Go **5**（Go 拿本页行数充当总数）。它按主因（256 处 null/""）归到了 P-SER-1 名下，
所以没进 P-PAGE-8 的计数。已更正为：**按主因归 3 条、按实际带该差异的请求数是 4 条，且含普通首页查询**。
这条仍是**未修**，且是剩余问题里唯一会让调用方拿到错数据的，优先级应高于 P-SER-1。
