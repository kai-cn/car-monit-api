## 2. 自主决策记录（含理由）

| # | 事项 | 决策 | 理由 |
|---|---|---|---|
| D1 | 口令如何"出库"又不破坏本地可运行 | 基线三份配置置空 + 新增 `configs/*.local.yaml`（gitignore）+ `Load()` 支持同目录 `<name>.local.yaml` 自动合并 | 既满足"仓库零口令"，又保留"一条命令本地起服务"；Viper 不支持多文件合并，故在 `Load` 内用 `MergeConfig` 实现，优先级 **主配置 < 本地覆盖 < APP_ 环境变量** |
| D2 | 启动报错脱敏的范围 | 显式口令 + URL-encode 形态 + `password=/token=` 键值通用正则；`db.Open` / `cache.New` 全接线 | pgx/go-redis 的实际错误未必带口令，但"未必"不等于"不会"；正则兜底覆盖第三方库自行拼接的情况。实测（错误口令 + 不可达地址）输出 `NO_LEAK` |
| D3 | 内网地址清理范围 | README / `docs/deploy.md` / `configs/*` / `deploy/` 全部换占位符；`docs/parity-2026-11-02/` 保留原样 | parity 目录是对等性核验的**历史证据**（含原始报文与基线地址），改写会破坏可复核性；已在 §4 标注其为内部资料 |
| D4 | `config.example.yaml` 定位 | 由"全量副本"改为**最小可运行示例**（约 80 行） | 避免与 `config.yaml` 双份维护漂移；用户要求"最小示例"，且 CI 里有 `TestLoadExampleConfig` 保证它真能加载 |
| D5 | **调度并发语义** | Go 侧维持"每任务一个 goroutine"，并更正文档：Java 是 `setPoolSize(10)`，两者都在任务级并行、同任务不重入 | 上一轮已核对 `SchedulingConfig.java:44`。真正差异只在"同一时刻就绪任务 > 10"时 Java 排队、Go 全并行；当前 9 个任务在跑，不触发。**不做人为串行化**——那会引入与 Java 不一致的新语义 |
| D6 | 分布式锁的实现与默认值 | Redis 租约锁（SET NX PX + token 续约 + Lua compare-and-delete），`enabled: false` 默认关闭 | 用户要求"单副本不受影响、多副本开启才生效"。选 Redis 而非 DB：本项目已有 Redis 依赖，不引入新表与迁移；租约比"长时间持锁"更能容忍进程崩溃 |
| D7 | 锁后端不可用时的行为 | 视为"未抢到"→ **跳过本次执行**（宁可漏跑不重复跑），并打 WARN | 重复执行会写坏水位线/重复推 ES（数据面问题）；漏跑可等下次触发，且下次基线是全量/增量容错。取舍已写进 `scheduler/lock.go` 头部与 `docs/deploy.md` |
| D8 | 依赖升级上限 | gin 停在 **1.11**、prometheus 停在 **1.22**；`go` 指令保持 **1.24.1** | gin 1.12 / prometheus 1.25 均要求 `go >= 1.25`，本机工具链 1.24.1 直接拒绝构建。提升 go 指令属环境变更（镜像 + CI + 本机），不在本分支处理，已在 §3 标注阻塞点 |
| D9 | gorm 跨版本升级是否单独回归 | 直接升到 **1.31.1** + driver 1.6.0，随本轮一起跑全量测试 | 报告 02 原建议"单独立项"，但本项目对 gorm 是**查询构造器式浅用**（无 AutoMigrate、无关联、无 Hook），升级面可控；全量测试（含路由/分页/序列化断言）已通过 |
| D10 | `-race` 门禁 | 放进 CI 独立 job（`CGO_ENABLED=1`），**不**强行要求本地 | Windows 本机无 cgo/gcc，本地 `-race` 直接报 `requires cgo`；写成"本地可选、CI 强制"，避免制造假失败 |
| D11 | gofmt/goimports 与 CRLF 假失败 | CI（Linux，LF）强制执行；`check.bat` 检测 `core.autocrlf=true` 时显式 SKIP 并提示以 CI 为准 | 不引入 `.gitattributes` 全量重规范化（会产生上千行无意义 diff）；用"环境感知 + 单一权威口径"解决 |
| D12 | `queryall` 大小写 | 改为区分大小写（对齐 Java `String.equals`） | 大小写不敏感会把运维误写的 `QUERYALL` 当成"查询全部"，**静默放大数据权限**；这是安全方向的不对称，必须严格 |
| D13 | `GetOrLoad` 击穿防护 | 加 singleflight（当前无生产调用点） | 属"低风险、为后续接入准备"；不改变任何现有调用行为 |
| D14 | 请求级超时 | 做成开关、默认 **0=关闭** | Java 侧无此语义，默认开启会改变慢查询的返回契约；开关化后由部署方按需启用 |
| D15 | 导出 `Close()` 的取消语义 | `context.WithoutCancel` → 进程级 `baseCtx`，`Close()` 先 cancel 再 Wait | 原实现既无法取消（WithoutCancel）又没人调用 `Close()`：既会截断 CSV 又无法优雅收尾。改为"可取消 + 有超时"，由 shutdown 的 60s 预算兜底 |
| D16 | 三份基线配置是否有口令的自动化守护 | 新增 `TestBaselineConfigsContainNoSecrets`，把文件复制到**无覆盖**的临时目录再 `Load` | 直接 `Load` 原路径会合并本机 `config.local.yaml`，测不出"入库内容"本身；复制隔离后才能断言基线干净 |

| L9 | 分布式锁不覆盖导出任务状态 / 不覆盖 GaussDB→ES 全量同步的并发保护 | 已文档化 | 锁只作用于 scheduler job；同步与导出靠"单副本 + 幂等 `_id`"兜底，扩容前需重新评估 |

## 5. 复验方式

```bash
cd car-monit-api-go-wt/car-monit-api-go

# 1) 编译 + 静态检查 + 单测
go build ./... && go vet ./... && go test ./... -count=1

# 2) 格式（Windows CRLF 工作区请先看 check.bat 的 SKIP 说明；以下命令在 LF 检出下有效）
gofmt -l cmd internal
goimports -l cmd internal

# 3) 并发关键路径（需要 cgo/gcc；Windows 本机不可用，CI 已覆盖）
CGO_ENABLED=1 go test -race ./... -count=1

# 4) 一键门禁（与 CI 同口径）
check.bat
```

| 检查 | 结果 |
|---|---|
| `go build ./...` | 通过 |
| `go vet ./...` | 通过 |
| `go test ./... -count=1` | **11 个包全绿**（73 个测试函数 / 18 个测试文件） |
| `gofmt -l` / `goimports -l`（LF 归一后） | 无输出 |
| 启动失败脱敏 | 用错误口令 + 不可达地址实测输出 `NO_LEAK` |
| `go test -race` | **本机不可执行**（无 cgo），由 CI job `race` 承担 |

`docs/deploy.md` 与 `README.md` §14 已同步本轮全部开关的默认值、开启方式与告警建议。
