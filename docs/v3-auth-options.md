# V3 鉴权现状与可选方案（P1-12）

- 结论日期：2026-11-09
- 范围：`car-monit-api` Java V3 分支
- 性质：**方案对比，不做实现**。鉴权是预存缺陷，不是 V3 引入；本文件只为人决策提供输入。

## 1. 现状（事实）

- `pro-base-common/.../interceptor/SecurityInterceptor.java`、`WebConfig.java` 整体被注释；
- 工程内没有 Spring Security / Shiro 依赖，也没有 `@PreAuthorize`；
- 因此 `/base/**`、`/api/v1/**`、`/api/v3/**`、`/progressive/**` 均可匿名访问。

### V3 新增运维端点（高风险，当前无鉴权）

| 端点 | 作用 | 风险 |
|---|---|---|
| `POST /api/v3/es/bootstrap` | 创建 ILM/模板/月索引 | 匿名可改索引结构 |
| `POST /api/v3/es/activate` | 运行期切换查询引擎 | 匿名可切主路径，造成故障 |
| `POST /api/v3/sync/backfill` | 提交 GaussDB→ES 回灌 | 匿名可触发重负载 |
| `POST /api/v3/sync/reconcile` | 分钟桶对账（含自动回灌） | 匿名可触发重负载 |
| `POST /api/v3/sync/reconcile/orphans` | 清理 ES 孤儿文档 | **匿名可删除 ES 文档** |
| `POST /api/v3/sync/dws/backfill` | DWS 重算 | 匿名可改写 DWS 历史 |

> **当前状态：以上端点无鉴权，禁止在对内网以外的任何网络暴露。**
> 生产必须至少做到：仅绑定内网地址 / 安全组白名单 / 网关统一认证后再上线。

## 2. 可选方案对比

| 方案 | 改动面 | 优点 | 风险 / 代价 | 适用场景 |
|---|---|---|---|---|
| A. 恢复拦截器并升级校验 | `WebConfig` 注册 + 重写 `SecurityInterceptor`（自定义头当前可伪造，需签名/JWT）；为运维端点单独加角色或 IP 白名单 | 改动集中在公共模块，所有接口一次性受控 | 需要密钥/身份体系；签名方案要处理时钟偏移与重放；漏配会全站 401 | 已有网关但希望应用层兜底 |
| B. 网关层统一挡 | 网关/Ingress 增加认证与路由白名单；api 侧不改代码 | 应用无感，集中治理，可复用现有 OAuth2/SSO | api 若被直连（端口暴露/内网横向）仍裸奔；需要网络与网关团队配合 | 生产已有统一网关且网络隔离可靠 |
| C. 仅内网暴露 | 部署侧绑定内网 IP、安全组、NetworkPolicy；不对公网开放 | 零代码改动，最快 | 内网横向移动/误配置即失守；审计与最小权限缺失 | 过渡期临时措施，不能作为最终方案 |

### 建议组合（供决策）

1. **短期**：C（网络隔离）+ 在网关加运维端点白名单；
2. **中期**：B（网关统一认证），应用侧只信任网关注入的身份头（并校验来源）；
3. **长期**：A（Spring Security + JWT/OAuth2），对 `/api/v3/**` 与运维端点做角色/权限细分；
   自定义 header 校验必须升级为签名/JWT，否则仍可伪造。

## 3. 明确不做

- 不在本分支擅自实现某一种鉴权方案（涉及身份体系与部署拓扑，需产品/运维共同决策）；
- 不通过注释、`continue-on-error` 或隐藏端点来“规避”风险。
