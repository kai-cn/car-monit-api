# 阶段0 · 环境与方法论

> 本轮为「从零重跑」的全量双端接口校验：不复用旧脚本的结论，静态清单、用例矩阵、比对内核全部重做，
> 结论以 `.run/verify2/` 下的机读结果为准，可重复生成。

## 1. 双端进程

| 角色 | 地址 | 启动方式 | 备注 |
|---|---|---|---|
| Java（基准） | `http://127.0.0.1:9902` | `D:\jdk\jdk1.8.0_202\bin\java -Xmx2048m -Dserver.port=9902 -jar target/pro-business-api-1.0.jar` | 复用已有 jar；11-02 17:25 该进程被外部终止（日志无异常、无 hs_err），本轮按原参数重启，只把堆上限从 1536m 提到 2048m（不改任何接口行为）。jar 与 worktree 的 Java 源码一致：`git diff --stat HEAD master -- pro-business-api pro-base-common` 为空 |
| Rust（被测） | `http://127.0.0.1:9911` | `APP_SERVER_PORT=9911 APP_REDIS_DATABASE=1 APP_CONSUMER_ENABLED=false APP_ENABLE_SCHEDULER=false target/debug/car-monit-api-rust` | 由 `tools/v2/rust_restart.sh` 一键重编译 + 重启（改代码后必须重启，Windows 下运行中的 exe 不能被覆盖）；性能对比改用 `tools/v2/rust_restart_release.sh`（同参数、跑 `target/release/`） |

Rust 侧关掉消费者与调度器的原因：Kafka(9092)/Pulsar(6650)/RocketMQ(9876) 都没起，rdkafka 会持续刷
`AllBrokersDown` 日志（不影响 HTTP），关掉后日志才可读。Java 是已打包的 jar，定时任务无法外部关闭，
它每 30s 跑一次「数据丢失检测」，对读接口比对无影响。

## 2. 数据与缓存

| 资源 | Java | Rust | 是否共享 |
|---|---|---|---|
| GaussDB | `192.168.56.10:5432/RuoYi`（`gaussdb`），业务表在 schema `jl_data01` | 同一实例、同一库、同一 schema | **共用**（双端读同一份数据，行级差异可直接归因到代码） |
| Redis | `127.0.0.1:6379` **DB0**（`spring.redis.database: 0`） | `127.0.0.1:6379` **DB1**（`APP_REDIS_DATABASE=1` 覆盖 `config/application.yaml` 的 0） | **按 DB 编号隔离**：两端各自冷启动、各自回填，互不污染；缓存类接口的比对因此分「冷缓存」与「热缓存」两轮跑 |
| Elasticsearch | `localhost:9200`（在跑） | 同 | 共用；本轮接口层未依赖 ES 命中（大表查询走 DB），在阶段4 复核降级路径 |

Redis DB 隔离带来的必要约定：Java 的 `car_list_jc` 用 Spring `RedisCache`（JDK 序列化 + 类型信息），
Rust 用 JSON 字符串，两者字节层面本来就不同，**不能跨 DB 读同一个 key**，所以隔离后各查各的、
比较的是「接口响应」而不是「缓存字节」，缓存内部格式差异单独记录在 `05-缓存与Redis对比.md`。

## 4. 比对语义（决定「什么算差异」）

1. **数字按原文比**：`json.loads(..., parse_float=str, parse_int=str)` 保留 JSON token，
   所以 `1500.00` vs `1500.0`、`0.0000` vs `0.0` 这类 BigDecimal 标度差异会被判为差异
   （前端按字符串取金额/重量时确实会不一致），同时用 `num-format` 与 `value` 区分「只是格式」还是「值不同」。
2. **结构差异与取值差异分列**：`keys`（Java 有/Rust 有）、`type`（null vs string 等）、`len`（数组长度）、
   `value`（标量不等）、`status`、`content-type`、`empty-body`、`raw-text`。
3. **易变字段只比存在性与类型**：`id`、`taskId`、`uuid`、`timestamp`、`traceId`、`reportId`、`duration` 等
   Java 每次请求现生成的字段（例如 feeGantry 每行随机 UUID）。
4. **Whitelabel HTML 归一化**：双端都返回 Spring 错误页时，先把 `id='created'` 时间戳替换再比。
5. **已知可接受差异**：用例可声明 `accepted.kinds` 白名单（如 Java 侧 CBOR/Smile 二进制输出），
   差异全部落在白名单内判 `ACCEPTED`（单列统计，不算通过也不算失败）。
6. **只读优先**：会写库/写缓存的端点（`sysutilTest/*`、`large/sync/*`、`export/submit`、`saveRedis`）
   默认不进全量矩阵，只在阶段4、5 里按「先跑 Rust、再跑 Java、逐条核对」的方式单独处理。
