## 2. D1 · `vehicleweight/map` 的「早一天」

现象（实测，同一条记录）：

| 取值路径 | Java | Rust | 数据库原值 |
|---|---|---|---|
| `/base/vehicleweight/list?datauuid=…`（直接查库） | `2024-11-19` | `2024-11-19` | `2024-11-19 08:23:53 +08` |
| `/base/vehicleweight/map`（走 Redis 缓存） | **`2024-11-18`** | `2024-11-19` | 同上 |

根因在 Java 自己的缓存往返，链路是：

1. MyBatis 读出 `Date`（JDBC `serverTimezone=Asia/Shanghai`）→ 正确的瞬时；
2. FastJSON 把整行写进 Redis，日期按实体上的 `@JsonFormat(pattern="yyyy-MM-dd")`
   落成 **字符串** `"2024-11-19"`（DB1/DB0 里实测到的就是这个串）；
3. 下次请求 FastJSON 反序列化 `"2024-11-19"` → **按 JVM 默认时区（+08）** 解析成
   `2024-11-19T00:00+08`；
4. Spring 的 `MappingJackson2HttpMessageConverter` 输出时，Jackson 的 `Date`
   序列化 **默认按 UTC** 格式化（除非显式配 `timeZone`）→ `2024-11-18T16:00Z`
   → `yyyy-MM-dd` 就是 `2024-11-18`。

也就是说：**写进缓存的是正确的日期，读出来早了一天**，而且只在「缓存命中」这条分支上出现
（`list` 走的是真实 timestamp，两边都对）。Rust 侧写缓存和读缓存用的是同一套
`JDate/Day` 约定（墙上时钟 → 原样序列化 → 原样解析），往返无损，所以输出与库里一致。

复现/取证脚本：`python tools/v2/map_cache_roundtrip.py`
（只动 DB1：删键 → 冷缓存请求 → 再请求热缓存 → 还原备份）。

### 为什么不能靠「同输入」把两边对齐

阶段5 的同输入实验（把 DB0 的键原文复制进 DB1）在这个端点上做不成，原因是
**Java 的缓存 blob 不是合法 JSON**：FastJSON 在 `@type` 模式下给 `Long` 加了
`L` 后缀，实测 DB0 里是

```
{"@type":"com.ruoyi.base.domain.OdsSzdnProvinceBorderVehicleWeightNewstructure",
 "axleModel":157L,"axleNum":6L,"checkTime":"2024-11-19", ...}
```

`157L` 直接让 JSON 解析失败（Python `json.loads` 与 Rust `serde_json` 都报同一位置）。
所以这条差异的性质是「两侧各读各写的缓存」，不属于接口契约差异；
harness 里给它打了 `ACCEPTED`，理由字段写的是这条时区往返缺陷。

### 如果产品要求逐字节复刻 Java

只需要在 Rust **读缓存**这条路径上复刻 Java 的不对称处理：把 `yyyy-MM-dd`（以及
`yyyy-MM-dd HH:mm:ss`）按 `+08:00` 解析，再按 UTC 格式化输出。落点是
`src/models/mod.rs` 的 `Day::deserialize` / `JDateTime::deserialize`
（目前走 `bind_query_date`，把墙上时钟当 UTC）。不建议默认做，理由：
它会把一个错值扩散到所有以缓存为源的端点，而这些端点在阶段5/9 的 14k 例里目前是逐字节一致的。

## 3. D2 · CBOR / Smile 二进制内容协商

Java（Spring Boot + `jackson-dataformat-cbor` / `-smile` 在 classpath 上）会根据
`Accept` 头真的换成 CBOR 或 Smile 编码：

```
Accept: application/cbor            → Content-Type: application/cbor   body: \xA3…
Accept: application/x-jackson-smile → Content-Type: application/x-jackson-smile  body: :)\\x01…
```

Rust 侧只注册了 JSON 序列化器，同样状态码、同样语义，但 `Content-Type: application/json`
+ JSON 体。判定为不修：

- 现网调用方（前端、导出器、`sys_util_service.py`）全部只发 `Accept: application/json`
  或不带 `Accept`，没有一例走二进制；
- 要等价就得引入 `ciborium`/`smile` 编解码并保持键序，成本远大于收益；
- 附带事实：Java 的 Smile/CBOR 体里嵌了 `timestamp` 的**二进制**编码，同一请求两次结果
  就不是逐字节相同（阶段11 稳定性里 `ct:acc07-2` 唯一一次「Java 自身抖动」就是它），
  所以这条即使实现编码器也到不了字节级一致。

用例清单：`contract` 阶段 `ct:acc06-*`（CBOR 4 例）、`ct:acc07-*`（Smile 4 例）。

## 4. D3 · 异步导出失败的 `errorMessage` 文案
`POST /api/v1/unified/{ds}/export/submit`、`POST /api/v1/large/export/submit` 都是
「立即返回 taskId + 后台线程写文件」的形态。本机没有 ES/Kafka，任务必然失败；
两边 `code`、`status`、轮询响应里的键集合都一致，只有失败原因字符串不同：

- Java：直接把底层异常消息透出（英文，含 ES 连接串）；
- Rust：自己的中文包装（`导出任务失败: …`）。

判定为不修：文案不是契约字段，前端按 `code` 分支。若要严格对齐，就得把底层
`sqlx`/`reqwest` 错误原样拼进 `errorMessage`，等于放弃 Rust 侧的错误信息规范。

## 4b. D5 · Java 的 PageHelper 线程残留会截断**其它端点**的结果

阶段12 并发比对唯一抓出来的实质差异，而且方向是 **Java 不稳定、Rust 恒定**：

- 泄漏源：`/base/feerecords/list`、`/base/feerecords/listToExport`、`/base/feerecords/{id}`
  —— 这三条路由在 Java 里必然 500（缺 Mapper XML，`Invalid bound statement`），
  但 `BaseController.startPage()` 已经在方法体第一行把 `pageSize` 写进了 ThreadLocal，
  查询没跑起来 → 页面没被消费 → 留在池化线程上；
- 表现：之后任意被调度到该线程的**别的端点**被这条陈旧分页参数截断。
  实测受害者 `/base/gantry/listAll` 正常 1526 行，被污染时只有 2 行，而 `total` 照常正确；
- 概率：`listToExport` 8/8、`list` 5/8、`{id}` 3/8（同连接紧邻一发测 8 轮）；
  非法 `orderByColumn` 那两条 500 路径**不**泄漏（orderBy 校验在拦截器内部，页面被正常清理）；
- Rust：同一清单 21 轮，受害者恒 1526 行 —— 分页参数每请求从 query 解析、执行时直接写进
  `LIMIT/OFFSET`，没有可跨请求残留的线程状态。

取证脚本与完整数据见 `12-并发一致性与状态隔离.md` §4。
判定为「不修」：在 Rust 里复刻它，等于给被测端引入一个让结果不可复现的缺陷，
与「同请求同结果」的迁移目标相反；建议的 Java 侧修法（补 Mapper XML 或
`try/finally { PageHelper.clearPage(); }`）写在那份文档里。

## 5. 曾经记为可接受、本轮已经做到逐字节一致的

| 原差异 | 现在的处理 |
|---|---|
| 超长请求行 / `%2f` / `%00`：Java 是 Tomcat HTML 400，Rust 是 Spring JSON 400 | `middleware.rs::tomcat_bad_request()` 复刻了那 435 字节的容器页（含 en-dash、`text/html;charset=utf-8`），实测两侧字节相同。注意 **`%2f`/`%00` 只看 path**，query 里的 `%2F` 不触发（`plateimage=http%3A%2F%2F…` 是 200），这条是在 filters 阶段回归后才钉准的 |

| `/api/v1/large/snapshot%2F..%2F..%2Fx` 400 的 body 形状 | 同上，`lg:bad:*` 4 例现在全 PASS |
| `query` 阶段 1 例 ACCEPTED | 现在 112/112 PASS |
| Whitelabel 错误页 `#created` 的日：Rust 空格补齐（`Nov  3`），Java 补零（`Nov 03`） | 已按 F40 改为补零。这行的来源是 Thymeleaf 的 `EEE MMM dd HH:mm:ss zzz yyyy`，**不是** `Date#toString()`；因为 harness 会把 `<div id='created'>…</div>` 整段归一化（每次请求时间必然不同），日 <10 时那 1 字节的差异一直没被判出来，是阶段10 做逐字节容器页对齐时才暴露 |
