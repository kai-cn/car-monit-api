## 3. 值得记录的 Java 侧事实

1. `PageHelper` 先 `COUNT(*)` 再取数，所以 `pageSize=0`、`pageNum` 越界都会先算 total；
   `reasonable` 默认 true（`PageDomain#getReasonable` 把 null 当 true），可由请求参数 `reasonable` 关掉。
2. 排序串来自 `StringUtils.toUnderScoreCase(orderByColumn) + " " + isAsc`，
   `isAsc` 的 setter 有空值保护（缺省保持字段默认 `"asc"`）并兼容 `ascending/descending` ——
   所以「只给 orderByColumn 不给 isAsc」在 Java 是 200，不是 SQL 错误。
3. 非法排序的判定是**全串正则** `[a-zA-Z0-9_ .,]+`（`SqlUtil#isValidOrderBySql`），
   并且长度上限 500；两者都只抛 `UtilException`，没有 `@ControllerAdvice`，最终是 Spring 的 500 JSON。
4. `{id}` 端点分两种：`AjaxResult`（`{"msg","code","data"}`）与「裸对象/空体」（找到就对象、找不到就 200 空体），
   19 张表里两种都存在，逐一核对过：如 `/base/gantry/{id}` 是 AjaxResult，`/base/snapshotflow/{bigId}` 是裸对象。
5. `zdata_trail_tracks` 的 `{uuid}` 在 Java 里会因 `uuid` 不唯一（实测同一 uuid 17 行）抛 `TooManyResultsException` → 500，
   Rust 已按同一行为实现，本轮 12 个取值全部一致。
6. 单请求耗时（本轮实测，同一份库）：Java 最慢 4.1s（`listToExport` 大页），Rust 最慢 3.05s，量级一致。
