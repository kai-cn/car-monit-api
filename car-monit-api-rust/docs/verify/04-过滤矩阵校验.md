## 2. 语义结论（写进迁移基线）

1. **三种「空」的语义必须分开**：
   - 参数缺失 → `<if>` 不成立；
   - 参数为空串且实体属性是 `String` → 属性是 `""`，`!= null` 成立、`!= ''` 不成立；
   - 参数为空串且属性是数字/日期 → Spring 绑成 `null`，条件不成立。
   Rust 侧原来只有「空串 = 没传」一种，这就是 154 + 9 + 1 例差异的共同根因。
2. Mapper XML 的 `<if>` 是**唯一可靠的字段清单来源**：实体能绑几十个字段，但只有 XML 里出现的
   才真正影响 SQL；349 个字段 × 4 变体的矩阵把这一点变成了可验证的覆盖。
3. `like` 条件在 Java 侧是 `like concat('%', x, '%')`，**大小写敏感**（PostgreSQL/GaussDB 无自动折叠），
   Rust 已按同一 SQL 生成，中文与前缀用例全部一致。
4. 唯一被记为「可接受」的用例：`/base/trailtracks/list?trailPoints=<超长真值>`，
   Java 由 Tomcat 直接给 400 HTML 错误页，Rust 给 Spring 风格 400 JSON，状态码一致。
