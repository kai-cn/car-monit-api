# 阶段1 · 接口清单静态对比

- 数据源：`pro-business-api/src/main/java/com/ruoyi/base/controller/*.java`（剥离注释后解析注解）
  ↔ `car-monit-api-rust/src/router.rs`（解析 `.route(...)` 注册表）；生成脚本 `tools/v2/inventory.py`。
- 计数：Java 有效端点 **85** 个，Rust 注册路由 **84** 条（通配路由一条覆盖多个 Java 端点，Rust 另有 3 条健康检查路由）。

## 1. 路径等价性

| Java 端点 | Rust 路由 | 说明 |
|---|---|---|
| `/api/v1/large/{snapshot,fee,trail}` | `/api/v1/large/{ds}` | Rust 用 `{ds}` 通配覆盖 3 个 Java 路径；未知 ds 的行为必须与 Java 的 404/400 一致（见 query 阶段） |
| `/progressive/{snapshotflow,feerecords,trailfitting}/list` | `/progressive/{table}/list` | 同上，Rust 通配 3 个表名；未知表名的错误体需与 Java 一致 |

## 2. Rust 独有路由

| 路由 | 说明 |
|---|---|
| `/healthz` | Rust 新增，只读无副作用；Java 未接 Actuator |
| `/readyz` | Rust 新增，含 DB 连通性探测 |
| `/health` | Rust 新增，等价 /readyz |

## 5. Java 源码里被注释掉、Rust 侧同样不注册的端点

`SysUtilController.java:39-70` 是一段块注释，包住了 `POST /base/sysutil/syncTrack` 与
`POST /base/sysutil/syncSuspiciousCar`。这两个路径在运行中的 Java 服务上返回 404，Rust 侧不注册，行为一致。（旧版清点脚本没剥注释，会把它们误记为 Java 端点。）
